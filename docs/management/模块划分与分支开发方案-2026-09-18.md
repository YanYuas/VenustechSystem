# 启明星系统 · 模块划分与分支开发方案

> 2026-09-18 · 下一阶段工作方式定稿
> 目标：把单体推进改为**模块化深度优化**——一个模块一个分支，各自深耕、各自验收、合并回主线。

---

## 一、模块划分（8 个，与六维导航对齐）

| 分支名 | 模块 | 范围（页面 / 后端） | 深度优化方向 |
|---|---|---|---|
| `mod-dashboard` | 首页总览 | DashboardView、快速入口、AI 摘要、身份进度 | 个性化卡片编排、首屏性能（已知全量拉任务） |
| `mod-execution` | 执行 | TaskListView、ProjectListView / Detail | 任务四象限、批量操作、项目甘特 |
| `mod-knowledge` | 知识 | DocumentEditor / Explorer、ResourceCenter | 双链图谱、版本对比、编辑器体验 |
| `mod-life` | 人生（三期核心） | Identity、Experience、Growth、Review、Report | 身份轴深化、经历聚合、报告模板 |
| `mod-asset` | 资产 | Learning、Life 记录、AssetLibrary、WorkflowCenter | 复习算法、SOP 复用、工作流编排 |
| `mod-companion` | 伙伴 | Conversation 第二分身、Pet 桌宠、Avatar 形象 | 对话体验、记忆、形象合成 |
| `mod-tools` | 工具箱 | Workspace、Vault、AiHot、Assistant（AI 助理） | 移动端打磨、离线队列、语音识别率 |
| `mod-platform` | 系统底座 | settings、同步引擎、插件框架、规则引擎、安全、构建 | 跨模块基础设施（**任何跨模块改动先落这里**） |

**判据**：改动只影响一个模块 → 去该模块分支；跨模块或影响数据层/安全 → `mod-platform`。

## 二、分支工作流（五步）

```
1. 开工：git checkout main && git pull → git checkout mod-xxx
2. 开发：小步提交（ Conventional Commits：feat(mod-xxx): … ）
3. 验收：python scripts/check_all.py   ← 架构守护 + 后端冒烟 150 + vue-tsc
         python scripts/audit_hardcoded_colors.py  ← 设计令牌纪律（171 基线不增）
4. 合并：git checkout main && git merge --no-ff mod-xxx   ← 保留模块边界，便于整块回退
5. 推送：git push origin main && git push origin mod-xxx
```

**合并用 `--no-ff`**：每个模块一个合并提交，历史里能一眼看出"哪一段是模块 X 的改动"，出问题可整块 revert。

---

## 三、硬约束（都是踩过坑换来的）

1. **分支名用单级**：本机环境下多级 ref（`feature/xxx`）写入会被静默吞掉 —— 一律 `mod-xxx`
2. **一次只有一个智能体动一个分支**：前天 git 灾难的根因就是并行智能体的交接工具与主线程抢 git；多人/多智能体协作时**按分支分工，不按文件分工**
3. **分支不过周**：模块分支是工作区不是仓库，完成即合并即删除，避免历史分叉
4. **新增模型必带 `updated_at` / `deleted_at`**：架构守护会拦（同步引擎 S6-3b 依赖）
5. **设计令牌纪律**：组件内不写 hex，颜色审计基线 171 处不增
6. **移动端影响面**：改前端公共样式后若需出新 APK，合并到 main 会自动触发云端打包

## 四、验收清单（每个模块合并前逐条打勾）

- [ ] `python scripts/check_all.py` 三项全绿（架构守护 / 冒烟 / 类型）
- [ ] 颜色审计未新增硬编码色值
- [ ] 该模块全部页面在 375px 宽下无横向溢出（移动端兜底层已全局生效）
- [ ] 未在本模块分支改动其他模块文件（越界改动应落到 `mod-platform` 或拆提交）
- [ ] 涉及后端新增表/字段：同步就绪审计通过
- [ ] 冒烟断言有新增（新功能必须有断言锁住，沿用现有风格）
