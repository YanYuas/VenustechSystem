# 决策日志（ADR）

> 变更控制流程：提出请求 → 评估影响 → 审批 → 执行 → 验证 → 记录。

> 日期：2026-08-26

## D-001 模块化单体 vs 微服务

- **背景**：独立开发者场景，需权衡架构演进与维护成本
- **决策**：采用模块化单体（Modular Monolith），非微服务
- **理由**：微服务运维成本、分布式事务、服务通信复杂度远超单人收益；各业务域用 Python 包隔离，接口清晰，未来可平滑拆分；单机 Docker Compose 一键启动；个人工具并发极低，单体性能够用
- **替代方案**：微服务（否决）、共享内核单体（未选）
- **影响**：部署简单；未来拆域需按包边界操作

## D-002 后端技术选型

- **决策**：FastAPI + SQLAlchemy 2.0 + asyncpg + Alembic + python-jose/passlib + pydantic-settings + loguru
- **理由**：FastAPI 异步高性能、自动 OpenAPI、类型友好、已熟悉；SQLAlchemy 2.0 生态最成熟且支持 asyncpg；Alembic 自动生成迁移；JWT + bcrypt 轻量无额外依赖；pydantic-settings 类型安全配置
- **替代方案**：Django（重）、Tortoise ORM（生态弱）
- **影响**：异步全栈，需熟悉 asyncpg 特性；任务队列 MVP 用 BackgroundTasks，后续升 Celery

## D-003 前端技术选型

- **决策**：Vite + Vue3 + TypeScript + Pinia + Vue Router 4 + Element Plus + Axios + Tailwind/SCSS + ECharts + Tiptap
- **理由**：Vue3 官方工程化方案；Pinia 比 Vuex 简洁支持 TS；Element Plus 覆盖 80% 组件、中文文档好；Tiptap 现代富文本适合文档/笔记
- **影响**：前后端均 TS 类型化；ECharts/Tiptap 按需引入控体积

## D-004 数据存储选型

- **决策**：PostgreSQL 16（主库）+ Redis 7（缓存/会话）+ 本地文件系统（附件/导出）
- **理由**：PG 用 JSONB 存灵活结构（对话消息、文档内容）；Redis 管 JWT 黑名单、热点缓存、Celery broker、限流；本地文件 MVP 够用
- **替代方案**：MySQL（JSON 弱）、S3/OSS（过度，V2 迁）
- **影响**：单机资源友好；附件后续迁对象存储需抽接口

## D-005 主键与数据建模

- **决策**：统一 UUID 主键 + JSONB 灵活字段（metadata/settings/content）+ TEXT[] 标签 + GIN 索引 + 进度冗余字段
- **理由**：UUID 避免 ID 枚举攻击、分布式友好；JSONB 应对需求变化避免频繁加列；数组标签比中间表简单，适合个人工具规模；进度冗余避免实时计算
- **影响**：软删除（deleted_at）MVP 先不加，后续按需；索引策略随数据量演进

## D-006 API 规范

- **决策**：`/api/v1` 基础路径 + JWT Bearer + 统一响应 `{code,message,data,timestamp}` + `?page&page_size` 分页 + 错误码分段（0/1xxx/2xxx/3xxx/5xxx）
- **理由**：前后端契约清晰；首页用单一 `/dashboard` 聚合接口减少请求数
- **影响**：错误码体系后续需文档化落地

## D-007 Prompt 管理方案

- **决策**：方案 A — 数据库存储 Prompt 模板（用户可自定义、统计使用次数、支持版本）
- **理由**：用户可修改、可统计、可版本化；系统内置种子数据供复制
- **替代方案**：代码硬编码（仅限系统级 Prompt）、YAML/JSON 配置文件（用户不可动态修改，否决）
- **影响**：需实现 prompts CRUD 界面

## D-008 项目记忆实现方案

- **决策**：MVP 采用方案 A — 关键词检索 + 上下文拼接（Top3 文档摘要拼入 system prompt）
- **理由**：实现简单、无额外依赖；V2 再升级向量数据库 RAG（Chroma/Qdrant）或结构化项目摘要
- **替代方案**：向量 RAG（运维复杂，V2）、结构化摘要（需定时任务，V2）
- **影响**：MVP 阶段召回精度受限，可接受；需在 AI 服务层预留可插拔接口

## D-009 Token 成本控制策略

- **决策**：对话历史截断（最近 10 轮）+ 流式只存终态 + 模型分级 + Redis 结果缓存（TTL 1h）
- **理由**：单人工具也需控成本；相同 Prompt+输入缓存避免重复调用
- **影响**：对话摘要机制需随 V2 补强
