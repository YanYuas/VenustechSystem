# 地球Online 内核全方位融入 · 效果评估

> 版本：v1.0 · 日期：2026-09-15 · 状态：**评估（未动手）**
> 对象：将 `C:\Users\21722\WorkBuddy\2026-09-15-20-56-14\earth-online-university` 的内核全方位融入启明星系统
> 结论速览：**值得做，但「全方位」需要重新定义** —— 深做 3 块、谨慎做 1 块、降级 2 块。

---

## 零、先界定「全方位融入」到底指什么

地球Online 的表层是一套国风像素风的单页站（启动页→建档→选形象→人物面板/经历库/技能树）。但它的**界面不可移植**（原生 JS + 独立设计规范，与启明星四主题冲突）。

真正能融进来的是 6 块内核：

| # | 内核 | A 中的载体 | 体量 |
|---|------|-----------|------|
| 1 | 等级/经验体系 | `LEVEL_TABLE` / `addExp()` / 8 条 EXP 规则 | ~70 行 |
| 2 | 领域知识库 + 计划生成 | `DOMAIN_LIB` / `aiGeneratePlan()` / `genericUnits()` | 303 行 + 生成器 |
| 3 | 技能树 + 自动归类 | `SKILL_CATS` / `autoClassify()` / `computeCategoryLevels()` | 22 分类 / 164 关键词 |
| 4 | 结构化经历 + 溯源 | `analyzeExperience()` / `showSkillDetail()` / `sourceExpIds` | 21 条提取正则 + 溯源 |
| 5 | 角色形象合成 | 背景 × 角色 canvas 合成 → base64 | ~50 行 + 30MB 素材 |
| 6 | DBSync 双向同步 | `dbOnline()` / `_dbSyncChain` | 并入同步线 |

**关键前提**：这 6 块合起来不是"加一个页面"，而是给启明星**装上一根成长脊柱**。下面逐块评估。

## 一、逐内核效果评估

### 内核 1 · 等级/经验体系

**会达成什么效果**

启明星从"13 个各自为政的工具箱"变成"一个有进度条的人生"。

最漂亮的一点：**不需要改任何现有模块的代码**。启明星已有 28 种事件的 `event_bus`，其中 **13 个可直接挂载经验值**：

```
task.completed          document.created        review.created
flashcard.reviewed      study.time.logged       habit.checkin
mood.logged             diary.created           project.created
project.memory.created  sop.used                prompt.used
inbox.item.processed
```

也就是说，用户在 Task 勾掉一个任务、在 Learning 复习一张卡片、在 Life 打个卡——**这些模块一行代码都不用动**，EXP 由订阅者自动结算。这是启明星架构给的红利，单页站做不到。

**当前的真实缺陷（这块能顺手修掉）**

桌面宠物有"亲密度/饱食度/心情/精力"四维数值，但**只写在 `localStorage['venustech_pet_stats']`，从不进数据库**。后果：

- 不进备份导出（启明星核心卖点是"本地优先 + 备份导入导出"）
- 换设备、清浏览器数据即归零
- 后端 `PetConfig` 表里根本没有这四列，后端 `get_current_state()` 算的是另一套（时间/任务/心情派生的状态感知）

**等级体系落 DB 后，成长数据才第一次真正受"本地数据主权"保护。** 这等于顺手修掉一个已验证的架构缺口。

**风险（需重新认识）**

我原本担心"经验通胀"，实测后**结论相反**：

| 项 | 实测值 |
|---|---|
| 到 LV30 总经验 | **107,069** |
| 轻度使用（≈73 EXP/日） | ≈ 1467 天（约 4 年） |
| 重度使用（≈259 EXP/日） | ≈ 413 天（约 1.1 年） |
| LV2 门槛 / LV10 门槛 | 102 / 2,619（约 1.4 天 / 36 天） |

曲线本身无需大改（LV30 是 1–4 年的长线目标，对 Personal OS 是合理的）。

**真正的风险是「经验值的语义被稀释」**：在 A 里，"记录一段经历"是主行为（30–65 EXP，高反思成本）；在启明星里，`task.completed` 一天可以触发十几次（勾一个复选框，机械成本极低）。若权重照搬，**勾选任务会和写一段经历赚得一样多**——EXP 就从"衡量成长"退化成"衡量点击量"。

所以真正的工作量在**权重重新标定**：必须让"沉淀类"行为（写经历、复盘、确认技能）显著贵于"处理类"行为（勾任务）。这需要一个产品判断，不是技术活。

### 内核 2 · 领域知识库 + 计划生成 —— **价值最高的一块**

**会达成什么效果：能力从 0 到 1，不是优化。**

启明星的学习计划目前是个**空壳**：

```python
class StudyPlan:   # backend/app/models/learning.py
    name / description / target_date / estimated_hours / progress / status / config
```

`LearningService.create_plan()` 只做一件事——把用户填的内容存进去。**没有任何生成、拆解、排期逻辑。** 用户想学雅思，得自己写计划。

而 A 的 `DOMAIN_LIB` 实测规模：

| 指标 | 实测 |
|---|---|
| 领域 | **13 个**（雅思 / 英语考试 / 英语口语 / 摄影 / 视频剪辑 / 做饭 / Presentation / 编程 / 设计 / 画画 / 写作 / 吉他弹唱 / 健身） |
| 能力单元 | **52 个** |
| 具体任务 | **90 条** |
| **带「达标标准」的任务** | **90 / 90（100%）** |
| 带「重复练习」标记 | 25 条 |

那 100% 是最惊人的数字——**每一条任务都写了"做到什么程度算完成"**。例如：

> 做一篇剑桥雅思听力 Section 1：第一遍正常做题；第二遍逐句暂停，把没听出来的词全部写下来，按"不认识 / 认识但没反应过来 / 连读吞音"分类
> **时长 40 分钟 · 达标标准：一页分类清单，至少 10 个词**

这不是泛泛的"多听多练"，是**可直接执行且有验收标准**的任务。这是三个月级的真实内容投入，也是 A 最不可替代的资产。

融入后的效果：用户说"我想学雅思"，系统产出 **30 天逐日 / 12 周逐周**的排期（≤45 天按天、>45 天按周，每周 5 任务），末位固定一个"验证任务"；再一键落成启明星的 Task。

**长尾兜底**：A 的 `genericUnits()` 在未匹配领域时，按"入门准备 → 基础操作 → 核心练习 → 实战产出"四阶段通用拆解，并能从自然语言里正则提取技能名（冒号后取、`学[会习]?XX`、去掉"我想/用30天"前缀）。所以长尾技能不需要建库也能出计划。

**风险**

- DOMAIN_LIB 是前端 JS 数据结构（303 行），需迁为 Python 常量：机械但量大。
- **字段无处安放**：A 的任务带 `do`（做什么）/ `time`（预估时长）/ `standard`（达标标准）/ `repeat`。而启明星 `Task` 只有 `title / description / status / priority / project_id / due_date / is_focus / reminder_time / recurrence / focus_duration`——**没有"预估时长"和"达标标准"两列**。必须做 schema 变更（或塞进 `description`，有损且不可结构化复用）。
- 90 条任务是中文文案，本地化无碍，但**领域偏学生/考证场景**（雅思、四六级、考研、评图）。启明星用户画像更宽（自由职业者、创业者、开发者），13 个领域**偏窄**，需要扩容或改为可扩展结构。

### 内核 3 · 技能树 + 自动归类

**会达成什么效果：把"复盘"从记流水账升级为能力资产积累。**

机制：`computeCategoryLevels()` 从**两处**关键词归类并累计等级——① 经历的标题+描述；② 学习计划里**已完成**的任务。22 个分类、约 164 个关键词。

融入启明星后，喂养技能树的数据源会从 2 处扩到 5 处（经历 + 已完成任务 + 复盘 + 项目记忆 + 学习时长），因为事件总线把它们全都连起来了。

**最有价值的接法**：A 的 `analyzeExperience()` 用 **21 条正则**从经历文本里提取技能（英文表达 / 公开表达 / 信息整理 / 写作 / 编程 / 设计 / 视频制作 / 团队协作 / 项目推进 / 翻译 / 数据分析 / 教学 / 策划 / 沟通表达 / 独立解决问题 / 适应能力 / 抗压能力 / 求职面试 / 职业实践 / 实验操作 / 深度阅读）——这份清单**可以直接喂给 `AvatarMemory` 的 `knowledge` 类记忆**，形成"第二分身眼中的能力画像"。

也就是说：技能树不只是个可视化面板，它能让第二分身回答"我擅长什么、我该怎么走"。

**风险**

- 22 个分类明显偏**建筑/校园**场景（含"建筑建造"、`sketchup`/`rhino`/`评图` 等关键词）。启明星用户未必适用，**分类表需扩容或做成可配置**。

### 内核 4 · 结构化经历 + 溯源 —— **最需要设计判断的一块**

**会达成什么效果**

A 提供的经历对象是结构化的：

```
{ 日期, 标题, 原始描述,
  结构化: { happened 发生了什么, whatIDid 我做了什么,
            result 结果, feeling 感受 },
  确认技能: [...],
  溯源: sourceExpIds   ← 关键
}
```

**`sourceExpIds` 溯源是启明星完全没有的机制**。`showSkillDetail()` 能回答：

> "我这个『写作』技能是怎么来的？" → 列出支撑它的每一段经历（"3 段经历"）

这是**能力可信度**——技能不是自我宣称的标签，而是有经历证据链的。对"人生推演"这个产品定位来说，这比等级数字更有说服力。

**风险：概念重叠，必须先归并**

启明星现在已有三处记录"发生过什么"：

| 已有 | 定位 |
|---|---|
| `Diary`（四维日记：家庭/健康/精力/成长） | 生活记录 |
| `Review`（日/周/月/项目复盘 + 年度报告） | 反思总结 |
| `AvatarMemory`（`event` 类事件记忆） | 分身记忆 |
| `ProjectMemory` | 项目沉淀 |

再塞一个"经历库"，**同一件事会被记三到四遍**。

所以这块**必须先做概念归并再动手**：
- 建议把"经历"定位为 **Review 的上游原始素材**（经历 = 事实层，复盘 = 解释层），而不是新表
- 或定义为 `AvatarMemory(memory_type='event')` 的强化版（补 `structured` 四要素 + `sourceExpIds`）

这是整个融合里**唯一需要产品定义先行、不能直接写代码**的部分。

### 内核 5 · 角色形象合成 —— **性价比最低**

**会达成什么效果**

启明星 `PetAvatar` 现状：`image_url`（单图）+ `eye_position`/`mouth_position`（简单模式表情定位）+ `action_frames`（进阶多帧动作）——**前提是用户得先有图片**。

A 的做法：5 张背景 × 14 个角色点选，canvas 实时合成一张，转 base64，全局复用同一张（首页/档案卡/历史存档共用）。

效果：建形象从"上传图片"降为"选背景 + 选角色，30 秒出形象"。

**风险与成本（结论：不值得全量做）**

| 项 | 分析 |
|---|---|
| 素材冲突 | A 的 30MB 是 AI 生成国风像素风；启明星是 4 套主题的 SVG 自绘 |
| 真正融入的成本 | 需为 4 套主题各出一套素材 ≈ 4 × 19 张图 |
| 只取合成机制 | 约 50 行 canvas 逻辑，成本极低，**但没素材就没意义** |
| 风格一致性 | 引入后会有第 5 种视觉语言，与「`variables.scss` 唯一 token 源」的硬约束直接冲突 |

**建议降级为 P3，或只做"背景合成"不引入 A 的素材**——让用户自己传背景+角色，系统负责合成。这样保留了机制、零素材成本、零风格冲突。

---

### 内核 6 · DBSync 双向同步

**会达成什么效果：基本没有增量。**

A 的同步是**整对象覆盖**式（`dbPullAll` 拉全量 → 本地改 → `dbQueueSync` 整条回写），没有 diff。真正可用的只有三个细节：

1. `dbOnline()` **能力探测降级**（有 SDK 走在线、无则自动降级本地）——思路可借鉴
2. `_dbSyncChain` **串行化写入链**——防止异步回写乱序，这个真有价值
3. 游标分页拉全量（`hasMore` / `nextCursor`）

而交付物 B 提供的 **diff-sync（canon 规范化 + 三态 diff + 写成功才更新 + recoverOnly）** 是数量级上更完整的方案。

**结论：不单独融入，`_dbSyncChain` 的串行化思路并入同步线统一处理。**

## 二、涌现效果 —— 合起来会变成什么

单块看是功能叠加，6 块合起来会有 4 个质变。

### 质变 1 · 从「记录工具」到「看得见成长的人生系统」

现在：13 个模块各记各的，用户看不到"我进步了吗"。
融入后：任何操作 → EXP → 等级 → 技能树 → 成长曲线，**每一次动作都有回响**。

### 质变 2 · 复利闭环真正闭合

启明星 README 宣称的核心是「**输入 → 处理 → 输出 → 沉淀 → 复用**」。
但实测下来，"沉淀"沉淀的是**资产**（SOP / Prompt / Skill / 项目记忆），而**人本身的成长没有被沉淀**。闭环缺一环。

A 的成长模型正好补这一环：

```
经历 → 技能（自动归类）→ 能力画像（喂给第二分身）→ 反哺（推荐下一个学什么）
```

### 质变 3 · AI 降级从「粗糙」到「有真本事」

现状：未配 API Key 时，`useConversation` 只有"问候/项目/学习/复盘/配置"几个关键词分支。
融入后：`DOMAIN_LIB` 给了降级路径一套**真能干活的知识库**——**没有 Key 也能生成一份专业的雅思 30 天计划**。

这直接决定**首次用户的第一印象**（绝大多数人不会一开始就配 Key）。

### 质变 4 · 桌宠统一（但必须做一次合并）

桌宠现在有两套互不相干的数值：
- 前端 `localStorage` 四维数值（会随时间衰减，但**不进库**）
- 后端 `get_current_state()` 的状态感知（时间/任务/心情派生，**真实但无成长性**）

再加全局等级就是**三套体系**。建议统一为：

| 层 | 承载 |
|---|---|
| 后端等级/EXP | 真实成长，DB 持久化，进备份 |
| 后端状态感知 | 真实情境（时间/任务/心情） |
| 前端表情/动作 | 纯表现层 |
| ~~localStorage 四维数值~~ | **废弃** |

## 三、明确不会改善的（诚实边界）

避免期望错位：

| 不解决 | 原因 |
|---|---|
| 自动化测试 15% | A 是**零测试**的单页站，无可复用测试资产 |
| 云端同步 0% | A 的同步是整对象覆盖，无 diff；真正有价值的是交付物 B |
| Electron / 移动端 | 与 A 完全无关 |
| RAG / 长文写作 | A 的"AI"**全是规则匹配**，不含任何真实模型能力 |
| UI 变好看 | 视觉风格冲突，只能取内核（见铁律三） |
| 多端同步 / 数据安全模型 | A 依赖资料库 SDK，与启明星"本地优先"方向相反 |

## 四、成本 / 风险 / 建议汇总

| 内核 | 价值 | 成本 | 主要风险 | 建议 |
|------|------|------|----------|------|
| 2 领域库 + 计划生成 | **极高（0→1）** | 中（迁数据 + Task 加列） | 领域偏窄（13 个偏学生） | **P0 必做** |
| 1 等级 / EXP | 高（全局体验） | 中（事件订阅 + 权重标定） | 语义稀释（需重定权重） | **P0** |
| 3 技能树 / 成长方向 | 高 | 中（22 分类需扩容） | 分类偏校园/建筑 | **P1** |
| 4 经历库 + 溯源 | 中高 | **高** | **与 Diary/Review/Memory 重叠** | **P1，且须先做概念归并** |
| 5 形象合成 | 低 | 高（4 主题 × 素材） | 风格冲突、token 约束 | **P3 或只保留机制** |
| 6 DBSync | 低（被 B 覆盖） | — | — | **并入同步线，不单独立项** |

## 五、结论

**值得做。但「全方位」应该被重新定义为：**

> **深做 3 块**（领域库 + 计划生成、等级 / EXP、技能树）
> —— 这三块合起来就把启明星从"工具箱"变成"成长系统"，且**几乎不动现有模块代码**（靠事件总线订阅）。
>
> **谨慎做 1 块**（结构化经历 + 溯源）
> —— 必须先把 Diary / Review / AvatarMemory / ProjectMemory 的概念归并做掉，否则会出现"同一件事记四遍"。
>
> **降级 / 砍掉 2 块**（形象合成、DBSync）
> —— 一个素材成本与风格冲突过高，一个被交付物 B 完全覆盖。

**一句话**：地球Online 的价值不在它的界面，而在它的**成长数据模型 + 领域知识库**。把这两样抽出来，启明星会从"记事的工具"变成"看得见成长的系统"——而且顺手修掉桌宠成长数据不进库这个真实缺口。
