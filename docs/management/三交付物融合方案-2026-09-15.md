`C:\Users\21722\WorkBuddy\2026-09-15-21-23-20\outputs\生活全能工作台（在线数据表存储，多端同步）.html`（222KB 单文件全内联 / 1687 行 / 9 张数据表）

**内核层（三个交付物中工程含量最高，是本次融合的主菜）**：

1. **实体 ↔ 数据表行适配**：`fromRow`（行→实体）/ `rawFields`（实体→PropertyValue），业务实体带稳定 uuid 落 `标识` 字段做幂等 upsert 键
2. **canon 规范化差异比较**（**核心洞察**）
   - 比较"规范化后的实体字符串"，而不是"行原始值 vs 待写值"
   - 理由：服务端表示有差异（日期读回 `2026-09-15T00:00:00Z`、空文本返回 `null`），比原始值会**永远不相等 → 无限写放大**
   - 所有可空值统一折叠（`Number(x||0)`、`x ? dayOf(x) : ''`），消除 `null`/`0`、`null`/`''` 歧义
   - 实测成果：**二次加载写入次数 = 0**
3. **三态差异写入**：`add`/`update`/`delete`；`cloud[表][标识] = {rowId, sig}` 仅在**写成功后**才更新 → 写失败的项下次 flush 自动重试（自愈）
4. **450ms 防抖 flush + 5 路并发**线程池（`worker()` 递归取下一项）
5. **失败韧性三件套**
   - 本机兜底缓存 + `dirty` 标记；flush 成功才清
   - 下次加载若 `dirty` → 以 **recoverOnly（只增不删）** 补推，避免误删其他设备数据
   - 状态机 `connecting/busy/synced/error` → 侧边栏圆点 + 顶栏文案 + 错误横幅 + 重试按钮
6. **不白屏约束**：先渲染空数据骨架，再拉云端；加载失败只提示不崩
7. **跨端订阅 + 防回环**：`db.onUpdated` → 500ms 防抖重载；`suppressUntil` 时间窗忽略自己写入触发的回调
8. **记录类型 ↔ 表键映射表**（易踩的静默坑：类型 `home` ↔ 表 `shopping`，漏了则整个模块永不落库且不报错）
9. **rowId 契约兜底**：`row.record_id || row._id || row.id`

### 3.0 三条融合铁律（先立规矩）

> **铁律一：内核优先于功能。**
> 交付物是"原生 JS 单文件 HTML"，启明星是"Vue3 + TS 严格 + 四层架构"。**源码不可直接移植**，只能提炼算法与模型后重写。把 `app.js` 3381 行塞进 Vue 是灾难。
>
> **铁律二：数据主权不迁移。**
> 启明星是**本地优先（SQLite）**，PRD 明确"云端同步放三期"。融合**不等于**把启明星改成资料库页面。交付物带来的是**同步算法**，不是**同步依赖**。
>
> **铁律三：视觉不越界。**
> 交付物 A 是国风像素风、B 是另一套设计规范；启明星已有 4 套主题，且 `variables.scss` 是唯一 token 源、约束"组件内 `#` 零命中"。**默认只取内核，不动视觉**；若要新增主题，须走完整的 52 组件对齐流程，独立立项。

### 线 1 · 同步内核 → 启明星「云同步引擎」（P0，最高价值）

**目标**：把交付物 B 已验证的 diff-sync 算法，落成启明星自己的通用同步能力。**本期只做抽象层 + 本地适配器，不接云。**

**为什么先做这个**：
- 启明星 30+ 表已留 `updated_at`，但"增量同步"从未被验证过。B 提供了唯一一份**跑通过的实现**（含"二次加载 0 写入"这种硬证据）。
- 一旦三期要接云，没有这层抽象就得从零重来。
- 本地 SQLite ↔ 本地 SQLite 的"双向 diff"就能把算法全链路验证一遍，**零外部依赖、零风险**。

**落地清单**：

| 位置 | 内容 |
|------|------|
| `backend/app/models/base.py` | 新增 `SyncMixin`：`标识(uuid)`(若无 UUID 则以 id 兜) + `updated_at` + `deleted_at` |
| `backend/app/core/sync.py`（新） | 通用化 `canon(entity)` / `diff_table(list, snapshot)` / `apply_ops(ops)`；三态 add/update/delete；`recoverOnly` 开关 |
| `backend/migrations/versions/0012_sync_fields.py` | 为缺 `updated_at`/`deleted_at` 的表补齐（软删除首次启用） |
| `frontend/src/composables/useSyncEngine.ts`（新） | 状态机 `connecting/busy/synced/error`；防抖 flush；并发池（默认 5）；本机兜底缓存 + `dirty` + `recoverOnly`；`suppressUntil` 窗口 |
| `frontend/src/composables/useSyncAdapter.ts`（新） | 适配器接口（`query`/`upsert`/`remove`/`onUpdated`）+ 本期 `LocalAdapter`（打后端 API） |
| `backend/app/api/sync.py`（新） | `GET /api/v1/sync/snapshot`（返回全表 sig 快照）+ `POST /api/v1/sync/apply`（接收 ops） |
| `backend/tests/test_sync.py`（新） | 断言：往返一致（canon 稳定）、二次 apply 零操作、写失败项能重试、recoverOnly 不删 |

**关键风险与升级点**：
- B 的算法本质是"最后写入胜 + 只增不删"，**无真正冲突解决**。多端同时改同一实体仍会丢。
- 上生产前须升级为**字段级 LWW（带时间戳）**或 vector clock。本方案在 `sync.py` 预留 `resolve_conflict()` 接口，本期实现为 LWW-whole-row，三期替换。

## 附录 C · 结论

1. **启明星完成度**：地基约 95%，功能一期 100% / 二期约 70%；**三个真实短板**是自动化测试（15%）、AI 能力（30%）、云端同步（0%）。
2. **三个交付物恰能补前两个短板**，并为第三个（云同步）提供唯一一份已验证的算法实现。
3. **可提炼的内核共 6 块**：diff-sync 同步算法、游戏化成长模型、离线规则引擎、多模块信息架构、单文件生成管线、形象合成机制。
4. **融合后不改变启明星的技术身份**：仍是 Vue3 + FastAPI + 本地优先，只是内部多了同步引擎、规则引擎、导出引擎三条管线。
5. **下一步**：先定 4 个决策点（D1–D4），再从 **P0（离线规则引擎 + 同步抽象层）** 动手。
