## 一句话

```bash
cd backend

```

然后双击根目录 **`start-demo.bat`**（用 `data_demo` 起后端），前端照常用。

## 为什么用独立数据目录

`backend/data/` 是你的**正史**。演示数据进 `backend/data_demo/`（已 gitignore），
两者物理隔离 —— 演示完删掉目录就干净，不会污染任何真实记录。

`--reset` 还带护栏：**拒绝在真实数据目录上执行**，也拒绝在目录名不含 `demo`
的路径上执行。宁可多一步麻烦，也不接受"一条命令删掉正史"。

## 几个刻意的设计

1. **时间轴铺开**：专注 / 打卡 / 心情 / 学习时长都回填到过去 60–90 天。
   只放"今天"的话，热力图与趋势线都是一根竖线，演示时看不出节奏。
2. **数据不自相矛盾**：周习惯（跑步 3 次/周）不会出现每天打卡；
   心情整体偏中上但夹着低谷 —— 真实的人不是一条直线。
3. **成长走生产代码**：等级、成长事件、技能统计都由真实的 `GrowthService.award()`
   产生（而不是手写等级公式），避免与实现漂移。
4. **双链真实解析**：文档里的 `[[标题]]` 被解析成 `backlinks` 行，
   与运行时行为一致。
5. **保险箱走真实加密**：用 `EncryptionManager.derive_key` + Fernet 加密，
   主密码 `demo-master-password-2026`（仅该演示库有效）。里面只有示例凭据。

## 途中发现的两条真实约束（值得你知道）

### 1. 「同一用户最多 1 个专注任务」
数据库上有部分唯一索引：

```sql
CREATE UNIQUE INDEX idx_tasks_unique_focus ON tasks (user_id) WHERE is_focus = 1
```

我最初给 7 个任务标了 `is_focus`，直接撞约束。这是个**很好的设计**——
"今日最重要"本来就只该有一个。种子已按此规则约束（只保留第一个）。

### 2. Git Bash 的路径形式会让服务打开错误的库
`VENUSTECH_DATA_DIR=/d/YanYuas/...`（MSYS 形式）会被 `Path()` 解析成
`\d\YanYuas\...`（**丢掉盘符**），服务于是打开另一个库、看到空数据。
我用它实测过一次，差点误判成"种子没生效"。

**结论**：这一项只能用 **Windows 路径**（`D:\...`）传，所以有了 `start-demo.bat`。

## 用法速查

```bash
cd backend

# 生成（首次）
.venv\Scripts\python.exe scripts\seed_demo.py --reset --yes

# 换目录
.venv\Scripts\python.exe scripts\seed_demo.py --data-dir data_demo2

# 只体检（列出每张表行数 + 空表）
.venv\Scripts\python.exe scripts\seed_demo.py --verify

# 只读不写、已存在数据时
#   不加 --reset → 脚本会拒绝覆盖并提示
```

| 文件 | 作用 |
|---|---|
| `backend/scripts/demo_seed_data.py` | 内容定义（纯数据，改内容不用碰代码） |
| `backend/scripts/seed_demo.py` | 生成引擎（迁移 / 清空 / 写入 / 体检） |
| `start-demo.bat` | 用 `data_demo` 起后端（避开路径陷阱） |

**注意**：`start-dev.bat`（正式库）与 `start-demo.bat`（演示库）都用 8765 端口，
**不要同时跑**。`start-demo.bat` 会检测端口占用并提示。
