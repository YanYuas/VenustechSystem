## 1. 模块定位与目标

### 1.1 模块定位

执行模块是启明星系统「六维导航」中的**执行维度**，承担用户从「想法」到「交付」的全链路推进职责。模块内部包含两大子模块：

- **任务管理子模块**：GTD方法论落地，支持任务全生命周期（创建 → 推进 → 完成 → 复盘），含子任务、番茄钟、重复任务、今日最重要等深度能力。
- **项目管理子模块**：将多个任务聚合为有明确目标的项目，支持项目进度追踪、里程碑管理、统计分析、跨模块资源（文档/对话/复盘）聚合。

模块与其他维度的关系：

| 关联维度 | 关联方式 |
|----------|----------|
| 首页（dashboard） | 读取今日最重要任务、今日统计数据、项目概览 |
| 知识（knowledge） | 项目详情聚合关联文档，任务可关联文档 |
| 人生（life） | 任务/项目可绑定身份轴（identity_id），按人生角色分类 |
| 资产（asset） | 项目导出为可交付物（Zip包） |
| 伙伴（companion） | 完成任务时触发桌宠庆祝动作，任务完成事件驱动AI行为 |

### 1.2 优化目标

本次深度优化聚焦三个方向：

1. **任务四象限视图**：从「状态驱动」升级为「优先级 + 紧急度驱动」，帮助用户快速识别「先做什么」。
2. **批量操作深化**：现有批量操作仅4种action，需扩展到更丰富的批量场景（批量设截止日期、批量设提醒、批量删除子任务等），并优化交互效率。
3. **项目甘特图**：从「列表式里程碑」升级为「时间轴可视化」，让项目进度与时间关系一目了然。

### 1.3 设计令牌约束

本PRD所有视觉描述均使用设计令牌名称，不使用硬编码色值。设计令牌唯一来源：`frontend/src/styles/variables.scss`。

核心令牌速查：

| 令牌类别 | 令牌名称 |
|----------|----------|
| 主色 | `--primary`（启明粉） |
| 成功色 | `--mint`（薄荷绿） |
| 警告色 | `--butter`（奶黄） |
| 信息色 | `--sky`（云朵蓝） |
| 点缀色 | `--lilac`（淡紫） |
| 危险色 | `--strawberry`（草莓红） |
| 成就色 | `--gold`（星尘金） |
| 圆角 | `--radius-sm`(10px) / `--radius-md`(16px) / `--radius-lg`(24px) / `--radius-pill`(999px) |
| 间距 | `--space-1`(4px) → `--space-10`(40px) |
| 缓动 | `--ease-spring`（软弹簧）/ `--ease-soft`（柔和） |

## 4. 功能需求详细拆解

### 4.1 任务四象限视图（P0）

#### F4.1.1 四象限视图切换

**功能描述**：

在任务列表页的视图切换器中新增「四象限」选项，与现有的「列表」「看板」并列。四象限按「紧急度（横轴）× 重要度（纵轴）」划分，将任务自动归入四个象限：

- **第一象限（右上）**：重要且紧急 —— 立即做
- **第二象限（左上）**：重要不紧急 —— 计划做
- **第三象限（右下）**：紧急不重要 —— 授权/快速做
- **第四象限（左下）**：不重要不紧急 —— 少做/不做

**紧急度判定规则**：
- 紧急：due_date 在今天或之前（已逾期/今天到期）
- 不紧急：due_date 在明天及以后，或无截止日期

**重要度判定规则**：
- 重要：priority 为 high 或 urgent
- 不重要：priority 为 low 或 medium

**验收标准**：
- [ ] 视图切换器从「列表 | 看板」变为「列表 | 看板 | 四象限」三个按钮
- [ ] 切换到四象限视图时，自动拉取全量任务（page_size=200，与看板视图一致）
- [ ] 四个象限按 2×2 grid 布局，象限标题分别为「重要且紧急」「重要不紧急」「紧急不重要」「不紧急不紧急」
- [ ] 每个象限显示该象限内的任务卡片列表，卡片样式与看板视图卡片一致
- [ ] 象限标题旁显示任务数量徽标（如「重要且紧急 (3)」）
- [ ] 任务卡片点击后打开详情抽屉，与列表视图行为一致
- [ ] 切换回列表/看板视图时，恢复分页参数（page_size=20）
- [ ] 无任务落入某象限时，该象限显示空状态文案（如「暂无紧急任务」）

**交互细节**：
- 视图切换按钮组使用 `--radius-pill` 圆角容器，激活项背景为 `--primary`，文字为 `--white`
- 切换视图时有 150ms 淡入淡出过渡（opacity 0→1）
- 象限卡片使用 `--bg-panel` 背景，`--line` 边框，`--radius-md` 圆角
- 象限标题栏高度 40px，左侧 12px 内边距，右侧数量徽标使用 `--bg-inset` 背景 + `--radius-pill` 圆角
- 任务卡片 hover 时：边框变为 `--primary`，阴影变为 `--shadow-raise`，过渡 200ms `--ease-soft`
- 象限拖拽：支持将任务卡片从一个象限拖到另一个象限，拖拽后自动调整 priority 和/或 due_date（见 F4.1.2）

**状态全覆盖**：
- 默认态：四象限正常展示，各象限任务卡片按创建时间倒序排列
- 空状态：所有象限均无任务时，显示 BaseEmpty 组件「还没有任务，去创建第一个吧」
- 加载态：四象限骨架屏（2×2 网格，每格 3 行卡片占位）
- 错误态：加载失败时显示「加载失败，点击重试」，重试按钮点击后重新拉取数据
- 边界态：某象限任务超过 20 条时，该象限内部出现纵向滚动条（max-height: 400px，overflow-y: auto）

#### F4.1.2 象限拖拽与属性联动

**功能描述**：

在四象限视图中，拖拽任务卡片到不同象限会自动调整任务的 priority 和 due_date：

| 拖到象限 | 优先级变化 | 截止日期变化 |
|----------|------------|--------------|
| 重要且紧急（右上） | → urgent | → 今天 |
| 重要不紧急（左上） | → high | → 不自动改（保持原样） |
| 紧急不重要（右下） | → medium | → 今天 |
| 不重要不紧急（左下） | → low | → 不自动改（保持原样） |

**验收标准**：
- [ ] 拖拽任务卡片到新象限后，调用 PATCH /tasks/{id} 更新对应字段
- [ ] 更新成功后 toast 提示「已移动到「{象限名}」」
- [ ] 更新失败时任务卡片回到原象限位置，toast 错误提示
- [ ] 拖拽过程中，目标象限边框高亮为 `--primary`，背景为 `--primary-soft`
- [ ] 拖拽中的任务卡片透明度降为 50%
- [ ] 拖拽完成后，任务卡片以 200ms `--ease-spring` 弹入新象限位置

**交互细节**：
- 拖拽手柄：整个卡片可拖拽（draggable="true"），与看板视图一致
- 拖拽时卡片跟随鼠标偏移量为 (-8, -8)（让卡片浮在鼠标右上方）
- 目标象限 dragover 事件触发高亮，dragleave 事件取消高亮
- drop 事件后 300ms 内完成 API 调用，期间卡片保持在新位置但显示 loading 旋转图标
- API 调用成功后卡片以弹性动画落位（scale 1.05→1.0，200ms `--ease-spring`）
- API 调用失败时卡片滑回原位置（translateY 200ms `--ease-soft`），同时 toast.error

**状态全覆盖**：
- 默认态：四象限稳定展示
- 拖拽中：源位置卡片 50% 透明，目标象限高亮
- 拖拽成功：新位置弹性落位 + toast
- 拖拽失败：卡片回弹原位置 + 错误提示
- 归档项目任务：归档项目下的任务卡片不可拖拽（draggable=false），hover 提示「项目已归档」

### 4.2 批量操作深化（P0）

#### F4.2.1 批量操作扩展Action

**功能描述**：

在现有 4 种批量 action（complete / delete / move_project / set_priority）基础上，新增以下 action：

| 新增action | 说明 | 需要的额外参数 |
|------------|------|----------------|
| set_due_date | 批量设置截止日期 | due_date: string (YYYY-MM-DD) |

## 6. 数据模型与API补充

### 6.1 新增数据模型

#### 6.1.1 TaskDependency（任务依赖）

```python
class TaskDependency(UUIDMixin, TimestampMixin, Base):
    __tablename__ = "task_dependencies"

    task_id: Mapped[str] = mapped_column(
        String(36), ForeignKey("tasks.id", ondelete="CASCADE"), nullable=False, index=True
    )
    depends_on_id: Mapped[str] = mapped_column(
        String(36), ForeignKey("tasks.id", ondelete="CASCADE"), nullable=False
    )
    created_by: Mapped[str] = mapped_column(
        String(36), ForeignKey("users.id", ondelete="CASCADE"), nullable=False
    )

    # 唯一约束：同一任务不能对同一被依赖任务重复依赖
    __table_args__ = (
        Index("idx_task_dep_unique", "task_id", "depends_on_id", unique=True),
    )
```
