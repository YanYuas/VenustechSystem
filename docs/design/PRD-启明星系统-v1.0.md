## 第一部分：产品总纲

### 1. 产品概述

#### 1.1 一句话定义

Venustech System（启明星）是一款搭载「第二分身」AI助手的本地个人操作系统（Personal OS）。它以任务管理、知识沉淀、复盘闭环为基础能力，配合一个了解用户、会主动整理知识的二次元桌宠分身，帮助用户构建「输入 → 处理 → 输出 → 沉淀 → 复用」的个人复利闭环。

#### 1.2 产品定位

| 维度 | 内容 |
|------|------|
| 产品类型 | AI驱动的个人知识管理 + 任务管理 + 生活管理一体化操作系统 |
| 品类 | 第二大脑 / 个人效率工具 / AI Personal Agent |
| 部署形态 | 本地优先桌面端应用（Windows），数据存储在用户本地 |
| 商业模式 | 一次性买断（基础版）+ 官方DLC + 定制服务 + 远期云端订阅 |
| 核心差异化 | 「第二分身」——不是冰冷的工具，而是有生命、了解用户、主动服务的AI伙伴 |

#### 1.3 愿景与使命

- **愿景**：让每个人拥有一个真正了解自己的数字分身，在信息过载的时代保持方向感与持续行动力。
- **使命**：将分散的任务、知识、生活整合到一个统一入口，用AI降低个人管理的认知成本，让沉淀的资产持续产生复利。

#### 1.4 一期定位（实训路演版）

一期为**实训路演Demo**，目标是验证「第二分身 + 个人OS」的产品形态。一期只实现5个核心模块，代码按生产级标准编写以便二期复用。二期开发完成后才考虑上架分发。

**一期硬指标（可验收）：**
1. 实现5个核心模块：首页仪表盘、任务管理、知识资源、第二分身（含桌宠）、复盘系统
2. 第二分身接入DeepSeek真实API，支持多轮对话、基于文档内容回答、主动生成摘要与标签建议
3. 桌宠实现8种帧动画动作，可悬浮、可拖拽、可展开对话
4. 20分钟路演脚本全流程可跑通，无阻断性Bug
5. 代码结构符合生产级规范（模块化分层、统一错误处理、配置管理）

### 2. 目标用户与使用场景

#### 2.1 目标用户画像

| 用户类型 | 特征 | 核心痛点 |
|----------|------|----------|
| 学生 | 需要管理课程、作业、学习笔记、备考计划 | 笔记散落在多个App，复习时找不到；缺乏持续复盘习惯 |
| 自由职业者 | 同时管理多个客户项目，时间自主但易失控 | 项目进度不透明，知识沉淀不足，缺乏系统化工作流 |
| 创业者 | 多线程推进，信息输入量大，决策密集 | 认知过载，重要想法易丢失，缺乏个人知识资产积累 |
| 知识工作者 | 持续学习、写作、输出，依赖个人知识库 | 工具多但数据割裂，所有工具都是"死的"，没有智能助手 |

**共性特征**：有个人资料整理需求，追求效率，愿意尝试新工具，对AI有基本认知，重视数据隐私。

#### 2.2 核心使用场景

**场景一：每日启动（早间）**
> 用户打开启明星，桌宠打招呼，首页展示今日最重要任务和状态概览。用户确认今日聚焦，开始一天的工作。

**场景二：任务执行（日间）**
> 用户在任务模块推进任务，拆分子任务，切换看板视图。完成任务时桌宠做出庆祝动作。遇到难题时召唤第二分身，基于已有知识库提供建议。

**场景三：知识沉淀（随时）**
> 用户新建文档记录想法、笔记、会议纪要。写完后第二分身自动生成摘要和标签建议，用户确认后应用。文档通过双向链接互相关联，形成知识网络。

**场景四：每日复盘（晚间）**
> 用户打开复盘模块，系统自动拉取今日完成的任务和创建的文档，生成本周复盘初稿。第二分身基于数据提出3个反思问题，用户补充回答。明日计划一键转为任务。

**场景五：灵感迸发（随机）**
> 用户写完一篇文档后，第二分身分析内容，在桌宠气泡中不经意提出一个相关灵感。用户认可后，分身给出简易方向并撰写详细提示词，用户可复制使用或直接发给强AI执行。

### 3. 核心价值与差异化

#### 3.1 核心价值主张

> **不只是管理工具，而是一个懂你的数字伙伴。**

传统工具（Obsidian/滴答清单/Notion）的共同问题：
- 数据是死的，不会主动帮你整理
- 工具是冷的，没有情感连接
- 功能是散的，任务/知识/生活各管各的

启明星的解法：
- **第二分身**让数据活起来——她读你的文档，学你的思维，主动帮你整理
- **二次元桌宠**让工具有温度——她会开心、会担心、会提醒，不是冷冰冰的界面
- **个人OS**让功能成体系——任务/知识/复盘在一个闭环里流转，数据互通

#### 3.2 差异化对比

| 维度 | Obsidian | 滴答清单 | Notion | 启明星 |
|------|----------|----------|--------|--------|
| 知识管理 | ✅ 强 | ❌ | ✅ 强 | ✅ 有 |
| 任务管理 | ❌ 弱 | ✅ 强 | ✅ 中 | ✅ 有 |
| 复盘系统 | ❌ 需插件 | ❌ | ❌ 需模板 | ✅ 原生 |
| AI助手 | ❌ 需插件 | ❌ 弱 | ✅ 有 | ✅ 第二分身（核心） |
| 本地优先 | ✅ | ❌ | ❌ | ✅ |
| 情感化设计 | ❌ | ❌ | ❌ | ✅ 桌宠分身 |
| 主动服务 | ❌ | ❌ | ❌ | ✅ 主动整理/灵感 |

#### 3.3 不可替代性

启明星的护城河不是某一个功能，而是**「第二分身对用户的理解深度」**——使用越久，分身越了解用户的思维方式、知识结构、行为习惯，提供的建议和灵感越精准。这种数据积累形成的个性化体验，是通用AI工具无法复制的。

### 4. 产品路线图

#### 4.1 一期：实训路演版（当前阶段）

**目标**：验证产品形态，完成路演。
**范围**：5个核心模块 + 第二分身（API版）+ 桌宠基础互动。
**技术**：Electron + Vue3 + FastAPI + SQLite + DeepSeek API。
**交付**：可运行的桌面应用 + 路演演示 + 生产级代码结构。

#### 4.2 二期：完整产品版

**目标**：从Demo升级为可日常使用的完整产品。
**范围**：
- 补全模块：项目管理、学习成长（间隔重复卡片）、生活记录、长期资产库（SOP/Prompt/Skill）
- 分身进化：本地模型推理（Ollama/LM Studio）、长期记忆系统、五档自动化、完整灵感工作流
- 形象进化：桌宠↔人形切换、Marvis式状态感知互动、本地TTS语音、自定义形象上传
- 强AI模块：任务自动拆解、长文写作助手、RAG知识问答
- 工作流模板系统：数学学习/项目开发/小说写作等预设工作流
- 数据安全：可选加密仓库、全量备份/恢复、同步盘半自动同步

#### 4.3 三期：生态与云端

**目标**：构建插件生态，上线云端同步。
**范围**：
- 脚本插件系统（Python/JS，调用产品API）
- 官方插件市场 + 第三方开发者上传
- 官方云端同步（端到端加密，订阅制）
- 移动端App（Capacitor套壳，复用前端代码）

#### 4.4 四期及远期

- 多分身并存（工作助手/情感陪伴/严格导师等人格切换）
- 跨设备实时同步
- 社区与工作流分享
- 企业版/团队协作（可选方向）

### 5. 名词解释

| 术语 | 定义 |
|------|------|
| 第二分身 | 运行在本地的AI Personal Agent，能沉淀用户记忆、模仿用户思维、主动维护知识库、以二次元形象与用户互动 |
| 桌宠 | 第二分身的桌面悬浮形象，小窗口显示，可拖拽，支持帧动画动作 |
| 个人OS | 将任务、知识、学习、生活、复盘整合到统一入口的个人操作系统 |
| 工作流 | 预设的模块组合+规则+视图，可一键应用到特定场景（如数学学习工作流） |
| 收集箱 | 知识资源中的默认收件箱，所有未分类内容先入收集箱 |
| 复盘 | 定期（日/周/月）对任务完成情况、知识沉淀、个人成长进行结构化回顾 |
| 弱AI | 运行在本地的AI能力（本地模型），全私密，用于自动标签、摘要、语义搜索等 |
| 强AI | 调用云端大模型API的AI能力，用于任务拆解、长文写作、复杂推理等 |
| DLC | 可下载内容（Downloadable Content），指官方售卖的工作流包、形象包、人格包等 |

#### 6.2 模块间关系

- **首页**聚合其他4个模块的数据（今日任务来自M2，最近沉淀来自M3，分身状态来自M4，复盘入口来自M5）
- **M2任务**与**M3知识**通过"项目标签"和"文档关联"互通
- **M4分身**可读取M3的文档内容，可操作M2的任务（建议），可辅助M5的复盘
- **M5复盘**从M2/M3拉取数据，生成的明日计划可转为M2的任务

### 7. 模块1：首页仪表盘（M1）

#### 7.1 模块定位

产品门面，用户打开应用的第一屏。一屏完成「状态感知 → 任务聚焦 → 功能导航」。

#### 7.2 功能需求

##### F1.1 欢迎区

- 显示当前日期（年月日 + 星期）
- 根据时间显示问候语（早上好/下午好/晚上好/夜深了）
- 显示用户昵称（来自本地配置）
- 显示一句激励语（可配置，默认随机从预设库抽取）

**验收标准**：
- [ ] 日期与系统时间一致，格式为"YYYY年M月D日 星期X"
- [ ] 问候语按时段正确切换（6:00-12:00早上好，12:00-18:00下午好，18:00-24:00晚上好，0:00-6:00夜深了）
- [ ] 昵称从本地配置读取，未配置时显示默认值"启明星用户"

**交互细节**：
- 激励语每小时自动轮换一次，点击激励语可手动切换下一条
- 日期区域hover时显示农历日期（tooltip）
- 首次启动时昵称区域高亮提示"点击设置昵称"

**状态全覆盖**：
- 默认态：正常显示日期+问候+昵称+激励语
- 加载态：骨架屏占位（首次启动数据未就绪时）
- 错误态：日期获取失败时显示"--"，不影响其他功能

##### F1.2 今日最重要任务卡

- 展示当前设为"今日最重要"的任务
- 展示字段：任务标题、来源（项目标签）、阶段、进度百分比、下一步行动描述、状态标签
- 两个操作按钮：「继续工作」（跳转到任务详情/编辑）、「提交成果」（标记完成并填写成果说明）
- 若无今日最重要任务，显示空状态："今天还没有设定最重要的任务，去任务模块选一个吧" + 跳转按钮

**验收标准**：
- [ ] 任务数据从M2任务模块实时读取
- [ ] 进度百分比与任务子任务完成比例一致
- [ ] 「继续工作」跳转到任务编辑视图
- [ ] 「提交成果」弹出成果说明输入框，提交后任务状态变为"完成"
- [ ] 空状态有引导按钮，点击跳转到任务模块

**交互细节**：
- 进度条动画：进入页面时从0%动画到实际百分比（500ms ease-out）
- 「继续工作」按钮hover时右移4px+箭头微动效
- 「提交成果」弹出Modal，含文本域（必填）+ 完成时间（默认当前时间，可修改）
- 任务标题超长时单行省略，hover显示完整标题tooltip
- 卡片右上角有"更换今日任务"按钮（小图标，hover显示），点击弹出任务选择列表

**状态全覆盖**：
- 默认态：有今日最重要任务，正常展示
- 空状态：无今日最重要任务，显示引导文案+按钮
- 加载态：卡片骨架屏
- 完成态：任务已完成时，卡片显示"今日任务已完成 🎉"，按钮变为"设定新的今日任务"

##### F1.3 今日状态概览

- 4项计数：必须完成N项、进行中N项、等待处理N项、今日完成N项
- 每项可点击，点击后跳转到任务模块并自动筛选对应状态
- 数据实时更新（任务状态变化时计数同步变化）

**验收标准**：
- [ ] 4项计数与M2任务模块数据一致
- [ ] 点击计数项跳转到任务模块并应用对应筛选
- [ ] 任务状态变化时首页计数实时更新（无需刷新页面）

**交互细节**：
- 计数数字变化时有数字滚动动画（从旧值滚到新值，300ms）
- 每项hover时背景微亮+右移2px
- "今日完成"项数字为0时灰色，有完成时绿色高亮
- 4项横向排列，窄屏时自动换行

**状态全覆盖**：
- 默认态：4项正常显示
- 全空态：所有计数为0时，显示"今天还没有任务，去创建第一个吧"
- 加载态：数字骨架屏

##### F1.4 快捷入口

- 4个快捷操作按钮：新建任务、新建笔记、今日复盘、召唤分身
- 点击后触发对应操作（新建任务弹出创建框、新建笔记跳转到文档编辑器、今日复盘跳转到复盘模块、召唤分身展开对话窗口）

**验收标准**：
- [ ] 4个按钮均有对应图标和文字
- [ ] 点击后正确触发对应操作
- [ ] 操作完成后首页数据同步更新

**交互细节**：
- 按钮hover时图标放大1.1倍+背景色变化（150ms过渡）
- "新建任务"点击后在当前页弹出Modal创建，不跳转（快速创建）
- "新建笔记"点击后跳转到知识资源模块并自动新建一篇文档
- "召唤分身"点击后展开右侧对话抽屉，桌宠触发"打招呼"动作
- 支持快捷键：Ctrl+N新建任务，Ctrl+Shift+N新建笔记

**状态全覆盖**：
- 默认态：4按钮正常
- 禁用态：无（所有功能始终可用）

##### F1.5 最近沉淀

- 展示最近创建/修改的3篇文档（来自M3知识资源）
- 每篇显示：文档标题、修改时间、所属文件夹/标签
- 点击跳转到文档编辑器
- 若无文档，显示空状态

**验收标准**：
- [ ] 按修改时间倒序排列，取前3篇
- [ ] 点击跳转到对应文档的编辑器
- [ ] 文档修改后列表实时更新

**交互细节**：
- 每篇文档hover时背景微亮+左侧出现3px主题色竖条
- 修改时间显示为相对时间（"刚刚""5分钟前""今天14:30""昨天"），hover显示绝对时间
- 标签显示为小胶囊，超过2个时显示"+N"
- 文档标题超长单行省略

**状态全覆盖**：
- 默认态：3篇文档列表
- 空状态：无文档时显示"还没有文档，创建第一篇笔记吧"+新建按钮
- 加载态：3行骨架屏

#### 7.3 布局要求

- 顶部：欢迎区（通栏，高约80px）
- 中部上：今日最重要任务卡（通栏，最大视觉权重，高约160px）
- 中部下：左侧今日状态概览（占60%宽）+ 右侧快捷入口（占40%宽）
- 底部：最近沉淀（通栏）
- 整体采用卡片式布局，大圆角（16px），柔和阴影（0 2px 12px rgba(0,0,0,0.06)）
- 页面左右边距24px，卡片间距20px，卡片内边距20px

#### 7.4 全局交互规范

- 所有卡片进入视口时有淡入上移动画（opacity 0→1, translateY 10px→0，300ms，错落50ms）

#### 8.4 状态机

```
pending ──开始──→ in_progress ──完成──→ completed
   │                  │
   └──等待──→ waiting ─┘
                  │
                  └──恢复──→ pending
```

**状态流转规则：**
- pending → in_progress：用户点击"开始"
- pending → waiting：用户标记"等待中"（如等待他人回复）
- in_progress → completed：用户点击"完成"或提交成果
- in_progress → waiting：进行中转为等待
- waiting → in_progress：等待结束继续进行
- waiting → pending：等待后重新规划
- completed → pending：恢复未完成状态

**非法流转处理：**
- completed → waiting：不允许，需先恢复为pending再转waiting
- 所有非法流转操作时按钮置灰或不显示

### 10. 模块4：第二分身（M4）—— 核心亮点

#### 10.1 模块定位

#### 10.3 功能需求

##### F4.1 多轮对话

- 对话窗口：从桌宠展开的侧边栏（右侧抽屉，宽约400px）
- 支持多轮对话，保留当前会话的历史消息
- 消息流式输出（SSE），逐字显示
- 支持清空当前对话、新建对话
- 预设角色设定词（System Prompt），定义分身的身份、性格、说话风格
- 一期角色设定词在调试阶段打磨，PRD中预留配置入口

**对话数据结构：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 消息ID |
| conversation_id | UUID | 会话ID |
| role | Enum | user/assistant/system |
| content | Text | 消息内容 |
| tokens | Integer | 消耗token数（仅assistant消息） |
| created_at | DateTime | 时间戳 |

**验收标准**：
- [ ] 点击桌宠展开对话侧边栏，再次点击或点外部区域收起
- [ ] 发送消息后显示用户气泡，然后流式显示助手回复
- [ ] 回复过程中显示"正在输入..."状态
- [ ] 支持多轮对话，AI能记住当前会话上下文
- [ ] 清空对话后历史消息清除，开始新会话
- [ ] API调用失败时显示错误提示"网络异常，请稍后重试"，不崩溃

**交互细节**：
- 对话侧边栏从右侧滑入（300ms ease-out），遮罩层半透明
- 用户消息右对齐（主题色气泡），助手消息左对齐（白色气泡）
- 流式输出时光标闪烁（▌），完成后消失
- 消息支持复制（hover显示复制按钮）
- 输入框支持多行（Shift+Enter换行，Enter发送）
- 输入框上方有快捷操作：引用当前文档、清空对话、新建对话
- 对话历史自动滚动到底部，用户向上滚动时显示"↓新消息"按钮
- 支持Markdown渲染（代码块、列表、加粗）
- 代码块支持一键复制

**状态全覆盖**：
- 默认态：对话列表+输入框
- 空对话：显示分身头像+"你好，我是你的第二分身，有什么可以帮你的？"+快捷问题推荐
- 发送中：输入框禁用+发送按钮loading
- 回复中：助手气泡显示"正在输入..."+流式输出
- 错误态：消息气泡显示红色错误+"重试"按钮
- 网络断开：输入框上方显示黄色横幅"网络连接已断开，AI功能暂不可用"
- API未配置：显示"请先在设置中配置API Key"+跳转设置按钮

##### F4.2 基于文档内容回答

- 用户在对话中可@当前文档或指定文档，分身基于该文档内容回答
- 实现方式：将文档内容（或摘要）拼入System Prompt作为上下文
- 若文档过长，截取前N字（一期限制4000字）+ 摘要
- 回答末尾标注"基于文档《XXX》回答"

**验收标准**：
- [ ] 对话窗口有"引用当前文档"按钮，点击后将当前打开的文档加入上下文
- [ ] 加入上下文后对话中显示"已引用文档：XXX"
- [ ] 分身回答与文档内容相关，不编造文档中没有的信息
- [ ] 文档内容超过限制时自动截断并提示"文档较长，已截取前4000字"

**交互细节**：
- "引用当前文档"按钮在输入框上方，点击后显示文档标题标签（可×移除）
- 支持引用多篇文档（最多3篇），每篇显示为可移除标签
- 引用文档后，System Prompt中注入文档内容
- 回答中提到文档内容时可点击跳转到对应文档
- 无打开文档时，"引用当前文档"按钮置灰，tooltip提示"请先打开一篇文档"

**状态全覆盖**：
- 未引用：正常对话
- 已引用：显示引用标签
- 文档过长：截断提示
- 引用移除：上下文更新，后续对话不再基于该文档

##### F4.3 主动生成摘要

- 触发时机：用户保存文档后（内容变化超过一定阈值，如新增超过50字）
- 分身自动调用API生成100字以内的摘要
- 摘要显示在文档顶部（可编辑、可拒绝）
- 用户确认后写入文档summary字段
- 路演版自动触发，正式版可配置是否自动

**验收标准**：
- [ ] 保存文档后3秒内显示"分身正在生成摘要..."
- [ ] 摘要生成后显示在文档顶部，带"应用""重新生成""忽略"三个操作
- [ ] 点击"应用"后摘要写入文档，列表页显示摘要
- [ ] 摘要不超过100字，准确概括文档核心内容
- [ ] API失败时静默处理，不打扰用户（日志记录错误）

**交互细节**：
- 摘要生成中：文档顶部显示紫色横幅"✨ 分身正在为你生成摘要..."（不可关闭）
- 摘要生成后：横幅显示摘要文本+三个按钮（应用/重新生成/忽略）
- "应用"后横幅变为绿色"摘要已保存"（2s后消失），摘要显示在文档信息区
- "重新生成"后横幅回到生成中状态
- "忽略"后横幅收起，不保存摘要
- 已应用摘要的文档，在列表中显示摘要预览（2行省略）
- 摘要可在文档信息区编辑（点击摘要文本进入编辑态）

**状态全覆盖**：
- 生成中：紫色横幅加载态
- 已生成：摘要+操作按钮
- 已应用：绿色确认→消失
- 生成失败：静默（不显示错误，日志记录），用户可手动点"生成摘要"按钮重试
- 无内容：文档内容不足50字时不触发

##### F4.4 主动标签建议

- 触发时机：与摘要同时（文档保存后）
- 分身基于文档内容建议3-5个标签
- 标签建议显示在摘要下方，可勾选/取消/手动添加
- 用户确认后写入文档tags字段

**验收标准**：
- [ ] 标签建议与摘要同时生成
- [ ] 建议3-5个标签，每个标签不超过10字
- [ ] 标签可勾选（默认全选），可手动输入新标签
- [ ] 确认后标签写入文档，标签系统同步更新
- [ ] 已有标签的文档，建议时优先推荐已有标签

**交互细节**：
- 标签建议与摘要在同一横幅，摘要下方显示"建议标签："
- 每个建议标签为可点击胶囊（选中=主题色填充，未选中=灰色边框）
- 标签末尾有"+"按钮，手动输入新标签
- 确认按钮在标签右侧"应用标签"
- 应用后toast提示"已添加N个标签"
- 建议标签中已有标签优先显示（排在前面）

**状态全覆盖**：
- 生成中：与摘要共享加载态
- 已生成：标签胶囊+确认按钮
- 已应用：toast确认
- 无建议：内容过短或无法提取标签时，不显示标签建议

##### F4.5 灵感提示

- 触发时机：用户保存文档后，分身分析内容，有一定概率（一期路演版设为60%）产生灵感
- 灵感以桌宠气泡形式显示（不弹窗，不打断），内容为1-2句与文档相关的延伸思考或创新点
- 用户点击气泡后展开对话，分身进一步阐述
- 用户认可后，分身提供简易方向（要点列表），并撰写详细提示词
- 提示词可一键复制，或直接发送到对话继续深化

**验收标准**：
- [ ] 文档保存后桌宠可能出现灵感气泡（带灯泡图标）
- [ ] 气泡内容与文档主题相关，不是通用鸡汤
- [ ] 点击气泡展开对话，分身阐述灵感细节
- [ ] 用户说"这个不错"后，分身给出3-5个要点的简易方向
- [ ] 简易方向后分身自动撰写一段详细提示词（200字以上）
- [ ] 提示词有"复制"按钮，点击后复制到剪贴板并提示"已复制"

**交互细节**：
- 灵感气泡：桌宠上方弹出，3s后自动收起（可点击停留），带灯泡图标+1行文字
- 点击气泡：展开对话侧边栏，分身自动发送灵感详细阐述
- 对话中分身在灵感后显示"觉得这个方向怎么样？"
- 用户回复正向（"不错""可以""继续"）→ 分身给出简易方向（编号列表）
- 简易方向后自动接一段提示词（分隔线+"为你生成的提示词："+提示词内容+复制按钮）
- 复制按钮点击后变为"已复制 ✓"（2s后恢复）
- 提示词也可点击"发送到对话"继续与分身讨论优化
- 灵感触发概率可在设置中调整（0%/30%/60%/100%）

**状态全覆盖**：
- 触发中：桌宠"灵感灯泡"动作
- 气泡显示：桌宠上方气泡
- 气泡消失：3s自动收起或被点击
- 对话深化：展开侧边栏
- 无灵感：40%概率不触发，用户无感知
- API失败：静默，不显示灵感

##### F4.6 桌宠互动

**桌宠基本属性：**
- Electron透明窗口，尺寸约150×200px
- 默认悬浮在屏幕右下角，可拖拽到任意位置
- 始终置顶（可设置取消置顶）
- 二次元平面绘图，帧动画切换

**8种动作及触发条件：**

| 动作名 | 触发条件 | 描述 | 帧图数量 |
|--------|----------|------|----------|
| idle待机 | 默认状态 | 角色静止，轻微呼吸微动 | 2帧循环 |
| 思考 | 用户发送消息/分生存成内容时 | 角色托腮或歪头，作思考状 | 3帧循环 |
| 开心庆祝 | 用户完成任务/达成目标时 | 角色跳起来或举手，开心表情 | 4帧循环 |
| 担心提醒 | 有逾期任务/用户长时间未操作时 | 角色皱眉或低头，作担心状 | 2帧循环 |
| 提醒指向 | 有未完成任务/到截止时间时 | 角色手指向屏幕或任务方向 | 2帧循环 |
| 工作中 | 用户活跃操作（打字/点击）时 | 角色敲键盘或翻书 | 3帧循环 |
| 灵感灯泡 | 分身产生灵感时 | 角色头顶出现灯泡图标，兴奋表情 | 3帧循环 |
| 打招呼 | 用户打开应用/每天首次见面时 | 角色挥手，开心表情 | 4帧循环 |

**动作切换规则：**
- 动作切换有200ms淡入淡出过渡
- 同一时间只显示一个动作
- 触发动作持续3-5秒后自动回到idle（除idle外）
- 多个动作同时触发时按优先级：灵感灯泡 > 开心庆祝 > 担心提醒 > 提醒指向 > 思考 > 工作中 > 打招呼 > idle

**验收标准**：

#### 10.4 API接入规范

- 提供商：DeepSeek（deepseek-chat模型）
- 兼容OpenAI格式，后续可切换其他模型
- API Key加密存储在本地配置中（Windows Credential Manager或加密文件）
- 请求超时：30秒
- 流式响应：使用SSE（Server-Sent Events）
- 错误处理：网络错误/API错误/超时均有友好提示，不崩溃
- Token统计：记录每次调用的消耗token数，用于成本统计（一期仅记录不展示）
- 速率限制：同一对话最多同时1个请求，新请求取消旧请求
- 重试机制：网络错误自动重试1次，API错误（429/500）不重试

**API端点：**
- 对话补全：`POST https://api.deepseek.com/v1/chat/completions`（流式）
- 模型：`deepseek-chat`
- 温度：对话0.7，摘要0.3，标签0.3，灵感0.9

#### 10.5 隐私与安全

- 一期使用云端API，文档内容在生成摘要/标签/回答时会发送到DeepSeek服务器
- 用户需在配置中手动填入API Key，明确告知数据会发送到第三方
- 对话历史存储在本地SQLite，不上传
- 用户可随时清除对话历史
- 首次使用AI功能时弹出隐私告知："使用AI功能时，文档内容将发送到DeepSeek服务器进行处理。数据仅用于生成回复，不被存储或用于训练。是否继续？"
- 用户可在设置中关闭所有AI功能（纯工具模式），此时桌宠变为纯规则提醒器

| 灵感提示 | 文档保存后60%概率触发 | 桌宠灵感灯泡动作+气泡 |
| 摘要/标签完成 | 分身生成摘要/标签后 | 文档顶部横幅（非通知） |
| 每日复盘提醒 | 每天21:00（可配置） | 桌宠提醒动作+"该复盘今天了" |
| 系统通知 | 应用更新/备份完成 | Electron系统通知（可关闭） |

**交互细节**：
- 桌宠气泡：桌宠上方弹出，3s自动消失，可点击停留/展开
- 系统通知：Electron Notification，点击聚焦应用
- 通知设置：在设置中可开关各类通知
- 勿扰模式：设置中可开启，开启后所有通知静默（仅记录不展示）

## 第四部分：数据模型完整设计

### 14. 数据库设计规范

#### 14.1 设计原则

1. **统一主键**：所有表使用UUID v4，避免ID枚举，分布式友好
2. **时间戳**：所有表含created_at、updated_at，自动维护
3. **软删除预留**：所有业务表预留deleted_at字段（一期不启用，二期启用）
4. **索引策略**：外键字段必建索引，高频查询条件建复合索引
5. **JSONB灵活字段**：metadata、settings等不确定结构用JSONB（SQLite用TEXT存储JSON）
6. **数据一致性**：关键业务规则用数据库约束（NOT NULL、CHECK、UNIQUE）保证

#### 14.2 表关系总览（ER图）

```
users (1)───(N) tasks (N)───(1) projects_tag(虚拟)
  │              │
  │              └──(N) subtasks
  │
  ├──(N) folders (1)───(N) documents (N)───(N) tags
  │                      │
  │                      ├──(N) document_versions
  │                      └──(N) backlinks (自关联)
  │
  ├──(N) conversations (1)───(N) messages
  │
  ├──(N) reviews
  │
  └──(N) settings (KV)
```

### 15. 完整表结构

#### 15.1 users（用户表）

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL DEFAULT 'default_user',
    nickname VARCHAR(50) NOT NULL DEFAULT '启明星用户',
    avatar_path VARCHAR(500),
    api_key_encrypted TEXT,
    theme VARCHAR(20) DEFAULT 'purple',
    automation_level VARCHAR(10) DEFAULT 'L2',
    pet_position JSON DEFAULT '{"x": 1770, "y": 880}',
    pet_topmost BOOLEAN DEFAULT TRUE,
    inspiration_probability INTEGER DEFAULT 60,
    ai_enabled BOOLEAN DEFAULT TRUE,
    language VARCHAR(20) DEFAULT 'zh-CN',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);
```

**索引**：`CREATE UNIQUE INDEX idx_users_username ON users(username);`

#### 15.2 tasks（任务表）

```sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(500) NOT NULL,
    description TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending','in_progress','waiting','completed')),
    priority VARCHAR(20) NOT NULL DEFAULT 'medium'
        CHECK (priority IN ('low','medium','high','urgent')),
    project_tag VARCHAR(100),
    due_date DATE,
    is_focus BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order INTEGER NOT NULL DEFAULT 0,
    completed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);
CREATE INDEX idx_tasks_user_status ON tasks(user_id, status);
CREATE INDEX idx_tasks_user_focus ON tasks(user_id, is_focus) WHERE is_focus = TRUE;
CREATE INDEX idx_tasks_user_due ON tasks(user_id, due_date);
CREATE INDEX idx_tasks_user_project ON tasks(user_id, project_tag);
CREATE INDEX idx_tasks_user_completed ON tasks(user_id, completed_at);
```

**约束说明**：
- status和priority用CHECK约束限定枚举值
- is_focus同一用户只能有一个TRUE（应用层保证，数据库可用部分唯一索引：`CREATE UNIQUE INDEX idx_tasks_unique_focus ON tasks(user_id) WHERE is_focus = TRUE;`）

#### 15.3 subtasks（子任务表）

```sql
CREATE TABLE subtasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    title VARCHAR(500) NOT NULL,
    completed BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_subtasks_task ON subtasks(task_id, sort_order);
```

#### 15.4 folders（文件夹表）

```sql
CREATE TABLE folders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(200) NOT NULL,
    parent_id UUID REFERENCES folders(id) ON DELETE SET NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    is_inbox BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);
CREATE INDEX idx_folders_user ON folders(user_id);
CREATE INDEX idx_folders_parent ON folders(parent_id);
CREATE UNIQUE INDEX idx_folders_user_name_parent ON folders(user_id, parent_id, name) WHERE deleted_at IS NULL;
```

**特殊说明**：每个用户有且仅有一个is_inbox=TRUE的收集箱文件夹，应用层保证。

#### 15.5 documents（文档表）

```sql
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(500) NOT NULL,
    content JSON,
    folder_id UUID REFERENCES folders(id) ON DELETE SET NULL,
    tags TEXT[] DEFAULT '{}',
    summary TEXT,
    ai_suggested_tags TEXT[] DEFAULT '{}',
    version INTEGER NOT NULL DEFAULT 1,
    word_count INTEGER NOT NULL DEFAULT 0,
    file_path VARCHAR(500),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);
CREATE INDEX idx_documents_user_folder ON documents(user_id, folder_id);
CREATE INDEX idx_documents_user_updated ON documents(user_id, updated_at DESC);
CREATE INDEX idx_documents_user_tags ON documents USING GIN(tags);
CREATE INDEX idx_documents_title_trgm ON documents USING GIN(title gin_trgm_ops);
```

**说明**：
- content存储Tiptap JSON结构（SQLite中用TEXT列，应用层JSON序列化）
- tags用数组类型（PostgreSQL），SQLite用逗号分隔字符串或JSON TEXT
- file_path存储Markdown文件的相对路径（内容同时写文件和数据库，数据库为权威源）
- gin_trgm_ops用于模糊搜索（PostgreSQL扩展pg_trgm），SQLite用LIKE替代

#### 15.6 document_versions（文档版本表）

```sql
CREATE TABLE document_versions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    content JSON NOT NULL,
    version INTEGER NOT NULL,
    word_count INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_versions_document ON document_versions(document_id, version DESC);
```

**保留策略**：每篇文档最多保留10个版本，超出时删除最旧版本（应用层维护）。

#### 15.7 backlinks（双向链接关系表）

```sql
CREATE TABLE backlinks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source_doc_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    target_doc_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    target_title VARCHAR(500),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(source_doc_id, target_doc_id)
);
CREATE INDEX idx_backlinks_target ON backlinks(target_doc_id);
CREATE INDEX idx_backlinks_source ON backlinks(source_doc_id);
```

**说明**：记录文档间的链接关系，target_doc_id为NULL时表示链接到不存在的文档（待创建），此时target_title存储链接文本。

#### 15.8 conversations（会话表）

```sql
CREATE TABLE conversations (

    scene VARCHAR(30) DEFAULT 'general',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ

CREATE INDEX idx_conversations_user ON conversations(user_id, updated_at DESC);
```

```sql
CREATE TABLE messages (

    tokens INTEGER,
```


### 16. SQLite适配说明

一期使用SQLite，与PostgreSQL的差异适配：

| 特性 | PostgreSQL | SQLite适配 |
|------|------------|------------|
| UUID | gen_random_uuid() | 应用层生成UUID |
| JSONB | JSONB类型 | TEXT列存储JSON字符串 |
| 数组 | TEXT[] | TEXT列存储逗号分隔或JSON数组 |
| GIN索引 | USING GIN | 不支持，用LIKE或应用层过滤 |
| 部分索引 | WHERE条件 | 支持（SQLite 3.8.0+） |
| 时间戳 | TIMESTAMPTZ | TEXT存储ISO 8601字符串 |
| 外键级联 | ON DELETE CASCADE | 支持（需PRAGMA foreign_keys=ON） |
| 并发写入 | 支持 | 写锁，用WAL模式改善并发 |

**SQLite PRAGMA设置**：
```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
PRAGMA encoding='UTF-8';
PRAGMA cache_size=-20000; -- 20MB缓存
```

#### 24.2 学习成长模块

**定位**：系统化学习管理，从"输入"到"掌握"。

**核心功能**：
- 学习计划：创建学习目标，拆分为学习任务，设置进度
- 知识卡片：将知识点制作成卡片（正面问题/背面答案）
- 间隔重复复习：基于SM-2算法，每日生成复习队列
- 学习时长记录：手动或自动记录学习时长，生成统计图表
- 学习数据统计：每日/每周/每月学习时长、复习量、掌握率
- 学习资源库：关联文档、外部链接、笔记
- 学习提醒：到复习时间时桌宠提醒

**核心算法（SM-2简化版）**：
```
首次复习：间隔=1天，难度系数=2.5
复习质量<3：重置间隔为1天
复习质量≥3：间隔=间隔×难度系数
难度系数调整：EF = EF + (0.1 - (5-q)×(0.08+(5-q)×0.02))
```

- 滴答清单无知识管理/复盘/生活记录
- 滴答清单无AI分身
- 滴答清单是SaaS订阅，启明星是买断制+本地优先

### 30. Notion深度分析

**定位**：All-in-One工作空间，笔记+任务+数据库+协作。

**核心优势**：
- 功能全面，笔记/任务/数据库/看板/日历全覆盖
- 模块化Block编辑器，灵活性极高
- 模板生态丰富
- 团队协作能力强
- AI功能集成（Notion AI）

**核心劣势**：

- 性能问题（大页面加载慢）
- 数据锁在Notion格式，导出不完整
- 任务管理不如专业Todo工具
- 订阅制，成本高
- 无情感化设计
- 国内访问不稳定

**与启明星的差异**：
- Notion是"云端协作工具"，启明星是"本地个人系统"
- Notion重协作，启明星重个人

### 32. 竞争策略

3. **口碑驱动**：通过桌宠分身的情感连接和AI能力的实用价值，驱动用户自发分享（小红书/B站）
4. **买断制定信**：在订阅制泛滥的市场，一次性买断+本地优先=数据安全感，吸引隐私敏感用户
5. **插件生态后发**：二期后通过工作流模板和插件生态，扩展功能边界

## 第八部分：用户故事

### 33. 用户故事编写规范

采用Given/When/Then格式：
- **Given（给定）**：用户的初始状态和前置条件
- **When（当）**：用户执行的操作
- **Then（那么）**：预期的系统响应和结果

每个用户故事包含：角色、场景、验收条件。

### 34. 核心用户故事

#### US-01：每日启动与聚焦

**作为**一名学生，
**我希望**打开应用时能看到今天最重要的任务和整体状态，
**以便**快速进入工作状态，不被信息淹没。

**Given** 用户已安装并配置启明星，有未完成任务
**When** 用户双击打开应用
**Then** 桌宠触发"打招呼"动作
**And** 首页显示当前日期、问候语、用户昵称
**And** 首页展示"今日最重要"任务卡（含进度、下一步）
**And** 首页展示今日状态概览（必须完成/进行中/等待/已完成计数）
**And** 整个加载过程不超过5秒

#### US-02：创建并管理任务

**作为**一名自由职业者，
**我希望**快速创建任务并管理其状态和优先级，
**以便**清晰掌握所有待办事项。

**Given** 用户在任务模块页面
**When** 用户点击"新建任务"按钮，输入标题"完成客户方案"，选择优先级"高"，设置截止日期，点击创建
**Then** 任务出现在列表顶部，状态为"待办"，优先级显示为橙色
**And** 首页今日状态计数同步更新
**When** 用户点击任务的"开始"按钮
**Then** 任务状态变为"进行中"
**And** 任务可拆分为子任务，子任务勾选后父任务进度更新
**When** 用户将任务拖拽到看板的"完成"列
**Then** 任务状态变为"完成"，记录完成时间
**And** 桌宠触发"开心庆祝"动作

#### US-03：知识沉淀与AI整理

**作为**一名知识工作者，
**我希望**记录笔记后AI能自动帮我生成摘要和标签，
**以便**减少整理负担，让知识自动有序。

**Given** 用户在知识资源模块新建文档"项目架构设计笔记"，输入了800字内容
**When** 用户保存文档（内容变化超过50字）
**Then** 文档顶部显示"分身正在生成摘要..."
**And** 3秒内显示100字以内的摘要，带"应用/重新生成/忽略"按钮
**And** 摘要下方显示3-5个建议标签（可勾选）
**When** 用户点击"应用"
**Then** 摘要和标签写入文档
**And** 文档列表显示摘要预览
**And** 有60%概率桌宠触发"灵感灯泡"动作+气泡提示

#### US-04：与第二分身对话

**作为**一名用户，
**我希望**与第二分身对话时她能基于我的文档内容回答，
**以便**获得与个人知识相关的精准建议。

**Given** 用户打开了文档"项目架构设计笔记"
**When** 用户点击桌宠展开对话，点击"引用当前文档"，输入"这篇文档的核心观点是什么？"
**Then** 对话中显示"已引用文档：项目架构设计笔记"
**And** 分身基于文档内容回答，不编造文档外信息
**And** 回答末尾标注"基于文档《项目架构设计笔记》回答"
**And** 回复为流式输出，首字不超过3秒
**When** 网络断开
**Then** 输入框上方显示"网络连接已断开，AI功能暂不可用"
**And** 工具功能（任务/文档）仍可正常使用

#### US-05：灵感迸发与提示词生成

**作为**一名创作者，
**我希望**写完内容后分身能不经意提出相关灵感，
**以便**获得新的创作方向。

**Given** 用户保存了一篇关于"模块化架构"的文档
**When** 分身触发灵感提示（60%概率）
**Then** 桌宠显示"灵感灯泡"动作，上方弹出气泡"如果把模块化思路应用到插件系统呢？"
**When** 用户点击气泡
**Then** 展开对话，分身详细阐述灵感
**When** 用户回复"这个不错"
**Then** 分身给出3-5个要点的简易方向
**And** 自动撰写200字以上的详细提示词
**And** 提示词带"复制"按钮，点击后复制到剪贴板

#### US-06：每日复盘

**作为**一名创业者，
**我希望**每天结束时能快速生成复盘，AI帮我提出反思问题，
**以便**持续改进，避免重复犯错。

**Given** 当天有2个任务完成、1个逾期、创建了3篇文档
**When** 用户打开复盘模块，选择今天的日报
**Then** 自动填充"今日完成"（2个任务列表）和"今日未完成"（1个逾期任务）
**And** 分身区域显示"正在分析你的数据..."
**And** 生成3个与数据相关的反思问题（如"今天有1个任务逾期，是什么原因？"）
**When** 用户回答完问题，填写明日计划，点击保存
**Then** 复盘保存到历史
**When** 用户在明日计划某行点击"转为任务"
**Then** 弹出任务创建框，标题预填
**And** 确认后任务出现在任务模块，原行标记"已转任务"

#### US-07：桌宠互动

**作为**一名用户，
**我希望**桌宠能根据我的操作做出不同反应，
**以便**感受到陪伴感而非冰冷的工具。

**Given** 桌宠悬浮在屏幕右下角
**When** 用户完成一个任务
**Then** 桌宠触发"开心庆祝"动作（持续3秒后回到idle）
**When** 用户发送消息给分身
**Then** 桌宠触发"思考"动作
**When** 用户有逾期任务
**Then** 桌宠触发"担心提醒"动作+气泡"有任务逾期了哦"
**When** 用户拖拽桌宠到屏幕左上角
**Then** 桌宠跟随鼠标移动，松开后位置保存
**And** 下次打开应用时桌宠在左上角
**When** 用户右键桌宠
**Then** 显示菜单：收起/置顶/设置/退出

#### US-08：数据安全与导出

**作为**一名隐私敏感用户，
**我希望**我的数据完全在本地，可随时导出备份，
**以便**确保数据安全和可迁移性。

**Given** 用户使用启明星一段时间，有50篇文档+30个任务
**When** 用户在设置中点击"导出备份"
**Then** 系统打包所有数据（数据库+文档文件+配置）为ZIP
**And** 提示保存位置，导出完成后显示"备份成功"
**When** 用户在新电脑安装启明星，点击"导入备份"
**Then** 选择备份文件，确认后数据完整恢复
**And** 文档、任务、配置、对话历史全部恢复
**When** 用户卸载应用
**Then** 数据目录保留（不自动删除）
**And** 重新安装后可继续使用原有数据

#### US-09：离线使用

**作为**一名经常在无网络环境工作的用户，
**我希望**没有网络时也能使用核心功能，
**以便**在任何环境下都能工作。

**Given** 用户的电脑断开网络
**When** 用户打开启明星
**Then** 应用正常启动，首页/任务/文档/复盘功能全部可用
**And** 桌宠显示"💤"小图标表示离线
**When** 用户点击桌宠尝试对话
**Then** 提示"网络未连接，AI对话暂不可用"
**When** 网络恢复
**Then** 桌宠小图标消失，AI功能自动恢复
**And** 离线期间创建的所有数据正常保存

#### US-10：全局搜索

**作为**一名有大量数据的用户，
**我希望**快速搜索到任务和文档，
**以便**不浪费时间在查找上。

**Given** 用户有100+文档和50+任务
**When** 用户按Ctrl+K，输入"架构"
**Then** 搜索面板实时显示结果（防抖300ms）
**And** 结果分两组：任务（标题含"架构"）、文档（标题或内容含"架构"）
**And** 匹配关键词高亮显示
**When** 用户用↓键选中一个文档结果，按Enter
**Then** 跳转到文档编辑器并定位到匹配位置
**And** 编辑器内高亮所有匹配项
