## 1. 模块定位与目标

### 1.1 一句话定位

资产模块是启明星「个人复利闭环」的**沉淀层**——把学习过程、生活数据、工作方法、工作流编排统一沉淀为可复用、可迭代、可复利的长期资产。

### 1.2 模块在六维导航中的位置

| 维度 | 模块 | 定位 |
|------|------|------|
| 首页 | dashboard | 状态感知与今日聚焦 |
| 执行 | execution | 任务驱动与行动闭环 |
| 知识 | knowledge | 文档沉淀与知识网络 |
| 人生 | life | 价值观与身份探索 |
| **资产** | **asset** | **学习复利 + 生活记录 + 长期资产库 + 工作流编排** |
| 伙伴 | companion | 第二分身与情感互动 |

### 1.3 模块构成

```
mod-asset
├── LearningView.vue    学习管理（学习计划 / 知识卡片 / 间隔重复 / 学习统计）
├── LifeView.vue        生活记录（习惯打卡 / 心情追踪 / 四维日记）
├── AssetLibraryView.vue 长期资产库（SOP / Prompt模板 / Skill / 项目记忆）
└── WorkflowCenterView.vue 工作流中心（预设工作流 / 一键应用 / 应用历史）
```

### 1.4 本期目标

| 目标 | 衡量标准 |
|------|----------|
| 复习算法从"能用"升级到"好用" | SRS队列加载 < 300ms，过期卡片自动排序，学习曲线可视化 |
| SOP复用体验闭环 | 从"查看步骤"到"执行清单+完成记录+版本回溯"全链路 |
| 工作流编排可视化 | 从纯JSON配置到节点连线可视化编辑 |
| 移动端375px适配 | 所有视图在手机端无横向滚动，触控目标 ≥ 44px |

### 1.5 非目标（本期不做）

- 不做AI自动生成SOP（依赖强AI额度，远期规划）
- 不做跨设备同步（三期云端能力）
- 不做团队协作版（远期企业版）

## 4. 功能需求详细拆解

### 4.1 F1：学习管理深度优化

#### F1.1 复习队列智能排序（P0）

**功能描述：**
当前`get_today_review()`直接返回所有到期卡片，无排序策略。优化后按"紧急度"排序：过期最久的排最前，新卡片（repetition=0）排后段。

**排序规则：**
1. 第一优先级：`next_review < 今天`（已过期）→ 按过期天数降序
2. 第二优先级：`next_review == 今天`（今日到期）→ 按EF升序（EF低的更难，先复习）
3. 第三优先级：新卡片（`review_count == 0`）→ 排在最后

**验收标准：**
- [ ] 过期卡片排在今日到期卡片之前
- [ ] 同组内按规则正确排序
- [ ] 队列总数与`list_due_today()`结果一致，仅顺序不同
- [ ] 排序在后端完成，前端无需二次排序
- [ ] 队列加载接口响应时间 < 300ms（500张卡片规模下）

**交互细节：**
- 进度条上方显示队列构成提示："已过期 3 张 · 今日到期 12 张 · 新卡片 5 张"
- 过期卡片的卡片边框使用 `--strawberry` 色2px描边，区分于今日到期的 `--primary` 色
- 新卡片在卡片信息区显示"🆕 新卡片"标签（`--butter` 色背景）
- 翻卡动画保持现有0.6s rotateY，不改动

**状态全覆盖：**
- 默认态：队列有卡片，按排序规则展示
- 空状态：无到期卡片，显示"今日复习已完成 🎉"（现有逻辑保留）
- 加载态：复习区域显示骨架屏（卡片轮廓+进度条占位，300ms后若仍未返回则显示"加载中..."）
- 错误态：加载失败显示"加载复习队列失败，点击重试"（现有toast.error升级为内联错误区）

#### F1.2 Leitner盒子分级（P1）

**功能描述：**
在SM-2基础上引入Leitner盒子概念，将卡片分为5个盒子（Box 1~Box 5），盒子号越高表示掌握越牢固。评分质量决定卡片在盒子间移动。

**分级规则：**

| 评分 | 质量 | 盒子变化 | 间隔变化 |
|------|------|----------|----------|
| 0-1（忘记） | < 3 | 回到Box 1 | interval重置为1天 |
| 2（困难） | = 2 | 停留当前盒子 | interval × 0.8 |
| 3（一般） | = 3 | 停留当前盒子 | interval × 1.0 |
| 4（良好） | = 4 | 升到上一个盒子 | interval × 1.2 |
| 5（容易） | = 5 | 升两级 | interval × 1.5 |

**验收标准：**
- [ ] Flashcard模型新增 `box` 字段（Integer，默认1，范围1-5）
- [ ] 创建卡片时box=1
- [ ] 评分后按上表规则更新box
- [ ] 复习界面卡片信息区显示当前盒子："📦 Box 3"
- [ ] 卡片列表Tab可按盒子筛选
- [ ] 数据库迁移脚本：已有卡片box默认值为 `min(repetition+1, 5)`

**交互细节：**
- 盒子标签用5种渐变色：Box 1用 `--strawberry`、Box 2用 `--butter`、Box 3用 `--primary`、Box 4用 `--sky`、Box 5用 `--mint`
- 评分后卡片上滑出时，盒子标签颜色过渡到新盒子颜色（300ms ease）
- 卡片列表中每张卡片左侧显示4px宽的盒子色条
- 筛选按钮：全部 / Box1 / Box2 / Box3 / Box4 / Box5，横向排列可滚动

**状态全覆盖：**
- 默认态：正常显示当前盒子
- 空状态：某盒子无卡片时，该筛选结果显示"这个盒子还没有卡片"
- 加载态：筛选切换时列表区域显示骨架屏
- 错误态：盒子筛选API失败时回退到"全部"并toast提示

## 7. 用户故事

### 故事1：考研党小张的每日复习

### 故事2：自由职业者李姐的SOP复用

> 李姐是自由设计师，每次接项目都要走一套固定流程：需求确认→报价→合同→交付→验收。

## 9. 风险与依赖

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SM-2算法修改影响现有数据 | 老卡片box字段缺失 | Alembic迁移脚本回填，默认box=min(repetition+1, 5) |

| Capacitor壳兼容性 | 部分CSS特性不支持 | 降级方案：不支持时隐藏动画，功能正常 |
