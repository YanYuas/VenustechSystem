## 二、两个 P1 的技术要点（值得复用）

### 工作区扫描异步化（P1-4）

**问题**：`scan_root` 在单个 HTTP 请求内完成「递归 `os.scandir` + 数千行 INSERT」。
大根目录下前端只能干等——无进度、无反馈、易超时。

**方案**：

```
POST /workspace/roots/{id}/scan        → 置 scanning 态 + 起后台线程，立即返回
GET  /workspace/roots/{id}/scan-progress → { status, phase, found, total, interrupted }
```

三个必须处理的细节：

1. **后台线程自建 Session**。请求 Session 随请求结束关闭，复用它必然出错。
2. **进度节流**。每发现 200 个条目回调一次——逐文件回调会让进度更新本身成为瓶颈。
3. **僵尸态识别**。进程重启会丢内存注册表，此时 DB 仍写着 `scanning`，
   该根会**永久卡在扫描中**。`scan_progress()` 检测「DB 说 scanning 但注册表无记录」
   → 报 `interrupted: true` 并把状态归位为 `error`。

### SSH 连通性测试（P1-5）

**安全边界（勿放宽）**：

- host/port **只从已存凭据读取，不接受请求体传入**。否则这个方法就成了
  任意 `host:port` 探测原语（SSRF / 端口扫描）。已加断言验证请求体被忽略。
- 仅完成 TCP 三次握手即关闭：**不建立 SSH 会话、不发送任何密钥或凭据**。
- 3 秒超时、不重试；host 加字符白名单正则（拒绝畸形输入）。
- 结果写审计日志（新增 `vault.test_connection` 动作），成败均记。

## 三、本轮发现的一类系统性缺陷（已加守护）

**症状**：引用了**不存在的名字**时，不报错、不提示，只是**不生效**。

| 类型 | 实测数量 | 后果 |
|---|---|---|
| CSS 令牌 | **18 个**未定义（约 50 处引用；`--danger` 单名被 11 个文件使用） | `var()` 解析失败 → 该 CSS 属性静默失效 |
| 图标名 | **7 处**引用不存在的图标 | `AppIcon` 渲染为空 → 按钮变成无图标裸文字 |

**处置**：

- **令牌**：`variables.scss` 增加 **LEGACY ALIAS** 兼容层，18 个名字一一映射到
  规范令牌（写成 `var(<既有令牌>)` 引用 → 自动跟随 4 套主题明暗切换），
  标注为待收敛项。
  *为什么用别名而非逐处改*：逐处改要动 9 个模块的 20+ 文件，而这些模块各有分支，
  在本分支改会制造跨模块冲突；别名层是一处 18 行、映射一一对应、零布局风险。
- **图标**：补齐 `bookmark` / `download` / `upload` / `list` / `graph`；
  `loading` 改为既有的 `spin`（**这两处是 mod-tools 自己引入的真 bug**）。
- **守护**：`frontend/scripts/audit-tokens.py`（令牌 + 图标，基线 **0**），
  已纳入 `check_all` → 现为 **6 项**。

## 四、自身踩坑记录（防复发）

### 坑 1：把节点插进条件链中间（本轮连犯两次）

```
<div v-if="itemsLoading">…</div>
<div v-if="items.length > 1">   ← 我插入的筛选栏
<BaseEmpty v-else-if="items.length === 0">…</BaseEmpty>
```

两个不同后果：

- 「更换主密码」弹窗插进 `v-if / v-else-if / v-else` 链中 → `<template v-else>`
  失去依附 → **整个模板编译失败**。症状极具误导性：`vue-tsc` 报「所有导入都被
  声明但未使用」（因为模板根本没被编译）。
- 筛选栏插在 `v-if` 与 `v-else-if` 之间 → 链条被重新绑定，骨架屏与列表会同时渲染。
  **tsc 完全不报**。

**铁律**：往条件链附近插节点，必须放在链条之外（链首之前或链尾之后）。
